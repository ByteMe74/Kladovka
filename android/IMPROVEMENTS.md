## Остаётся

### 1. Токены не имеют срока жизни — `api.php`

```php
function issueUserToken(array $cfg, int $userId): string {
    return hash_hmac('sha256', 'kladovka-user-' . $userId, $cfg['session_secret']);
}
```

**Отзыв сделан 3 октября 2026:** таблица `revoked_users`, `logout` отзывает
вход, новый вход снимает отзыв. Выход из аккаунта теперь настоящий.

**Осталось: срока жизни нет.** Токен остаётся статистичной функцией от id и
секрета, поэтому действует, пока жив секрет, — хоть год, хоть пять лет. Это
осознанно: хранимые токены со сроком ломают все уже выданные (у телефонов в
настройках лежит старый токен, и после деплоя люди разом оказываются разлогинены),
а срок жизни без возможности отозвать токен утолкнуть в вредную — человек ушёл
с работы, а его токен продолжает работать.

Как чинить, когда решат: `user_tokens(token_hash, user_id, created_at,
expires_at)`, выдача нового токена при каждом входе, проверка по таблице. Обязательно
вместе с отзывом, а не вместо него, и с предупреждением на сайте — иначе
переустановка приложения станет обязательной для всех сразу.

### 2. Пароль админа на сервере — ЗАКРЫТО 3 октября 2026

Он был в открытом виде в репозитории и в скриптах деплоя. Даже после удаления из
git он остаётся в истории коммитов, поэтому проверка сделана сравнением хеша на
сервере: `password_verify` для значения из `gradle.properties` возвращает false,
и вход с этим паролем на живой сервер отклоняется (HTTP 401). Пароль сменён,
доступа из репозитория он не даёт.

Пароль остаётся в истории git — это не отменяет его смены: сменить нужно было
именно потому, что он там засветился. Удалять из истории нужно только при
утечке чего-то, что продолжает работать.

### 3. `userIdForToken` — O(n) на каждый запрос — ЗАКРЫТО 3 октября 2026

Было:

```php
$stmt = $pdo->prepare('SELECT id FROM users LIMIT 1000');
```

На каждый запрос с токеном сервер читал до тысячи пользователей и считал HMAC
для каждого. Два следствия: нагрузка росла линейно, а после тысячи
пользователей **все токены переставали работать молча** — без ошибки, без
записи в лог.

Теперь токен лежит в `users.token` под индексом `idx_users_token`, и поиск —
один запрос. Само значение токена не изменилось (`HMAC('kladovka-user-'+id +
secret)`), изменился только способ найти по нему пользователя, поэтому все
ранее выданные токены остаются рабочими. У кого-то токен в колонке ещё не
записан — он заходил до этой правки: для таких остался перебор как запасной
путь, и найденный токен тут же записывается, то есть перебор случается на
каждого пользователя ровно один раз за всё время жизни аккаунта, а не на
каждый запрос.

### 4. CORS не настроен — и это не ошибка

В `api.php` нет ни одного `Access-Control-*` заголовка. Для нативного приложения
CORS не нужен: это механизм браузерной политики одного источника. Пункт из
старой версии документа снят как неверный.

## Что из старого списка снято как неверное

- **«Пароли в build.gradle.kts»** — секреты уже вынесены в переменные окружения.
- **«Отсутствие rate-limiting»** — закрыт целиком: для входа и регистрации по IP,
  для `export` / `import` / `upload_photo` по пользователю.
- **«Отсутствие проверок на версию при синхронизации»** — проверка есть в
  `ApiClient.latestApk`, вопрос только в том, используется ли она в UI.

## Приоритет

Оба прежних пункта закрыты (пароль админа, отзыв токенов), плюс закрыт
O(n)-перебор в `userIdForToken`.

1. **Срок жизни токена** — единственное, что осталось по этой теме. Требует
   правки сервера **и** предупреждения на сайте: переход на хранимые токены
   разом ломает все уже выданные, а у людей в настройках лежит старый токен.
   Обработка 401 в клиентах уже есть — её сделали вместе с отзывом, так что
   технически приложение переживёт такую выкладку само, но сообщение о том,
   что нужно войти заново, человек всё равно прочитает на телефоне.
2. **Подпись EXE настоящим сертификатом** — самоподписанный не даёт видимой
   пользы, подробности в `PLAN.md`.
