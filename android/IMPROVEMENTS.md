## Остаётся

### 1. Токены не имеют срока жизни и отзыва — `api.php:29-31`, `:829-832`

```php
function issueUserToken(array $cfg, int $userId): string {
    return hash_hmac('sha256', 'kladovka-user-' . $userId, $cfg['session_secret']);
}
```

Токен — чистая функция от id пользователя и секрета. Он не меняется со временем,
не привязан к сессии и не отзывается: `logout` отвечает `ok` и ничего не делает.
Любой, кто получил токен (из логов, из истории браузера, из дампа БД), может
пользоваться им бессрочно.

**Как чинить:** хранить токены в таблице `user_tokens(id, user_id, token_hash,
created_at, expires_at, revoked)` и проверять по ней. Секрет в подписи оставить
можно, но тогда нужен ротационный ключ и срок жизни.

### 2. Токен принимается через query string — `api.php:458-462`

```php
return $_GET['token'] ?? ($_GET['api_key'] ?? ($_POST['api_key'] ?? ''));
```

Токен в URL попадает в логи веб-сервера, в заголовок `Referer` при загрузке
ресурсов и в историю браузера. Заголовок `Authorization: Bearer` уже поддерживается
и должен быть единственным способом.

### 3. Пароль админа на сервере нужно сменить

Он был в открытом виде в репозитории и в скриптах деплоя. Даже после удаления из
git он остаётся в истории коммитов и на сервере. Смена возможна только с доступом
к хосту — из репозитория это не делается.

### 4. `userIdForToken` — O(n) на каждый запрос — `api.php:42-46`

```php
$stmt = $pdo->prepare('SELECT id FROM users LIMIT 1000');
```

На каждый запрос с токеном сервер читает до тысячи пользователей и считает
HMAC для каждого. Два следствия: растёт нагрузка линейно, а после тысячи
пользователей все токены перестают работать молча. Пункт 1 закрывает и это.

### 5. Rate-limiting есть только для входа и регистрации — `api.php:337-357`, `:473-508`

`blockedSeconds` / `recordFail` / `regBlockedSeconds` применяются к `login` и
`register`. Для `import` / `export` / `upload_photo` ограничений нет — один
пользователь может заливать данные без пауз.

### 6. CORS не настроен — и это не ошибка

В `api.php` нет ни одного `Access-Control-*` заголовка. Для нативного приложения
CORS не нужен: это механизм браузерной политики одного источника. Пункт из
старой версии документа снят как неверный.

## Что из старого списка снято как неверное

- **«Пароли в build.gradle.kts»** — секреты уже вынесены в переменные окружения.
- **«Отсутствие rate-limiting»** — реализован для входа и регистрации; не хватает
  только для остальных действий (см. пункт 5).
- **«Отсутствие проверок на версию при синхронизации»** — проверка есть в
  `ApiClient.latestApk`, вопрос только в том, используется ли она в UI.
